Design Decisions

The reasoning behind batch processing, Gmail labels, manual review, external configuration, and structured logging.

The system emphasizes traceability, repeatability, and controlled automation over raw speed. These decisions shape both the user experience and the way the application can be supported later.

Why batch processing?

Emails are processed as a unit of work rather than as unrelated one-off actions. A batch has a clear beginning and end, which makes execution easier to trace when something fails.

  • Consistent execution
  • Easier tracking
  • Clear run boundaries

Why Gmail labels?

Labels act as the workflow control mechanism. The application processes only the messages deliberately placed into the source label instead of scanning the entire inbox.

Why keep manual review?

Automation stops before sending so generated content can be checked. The boundary prevents accidental sends, incorrect formatting, and incomplete data from being shared.

Export → Review → Send

Why external configuration?

Environment-specific behavior is externalized so normal configuration changes do not require source-code edits. This makes setup safer and keeps application logic separate from deployment values.

Why structured logging?

Each run includes a batch ID, start and end boundaries, and per-item tracking. The purpose is practical: understand what happened without guessing.
