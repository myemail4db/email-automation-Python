Logging & Recovery

How batch IDs, item-level status, run boundaries, and error isolation make the workflow easier to support.

Designed to answer one question

What happened during this run?

Every run uses a unique batch ID. That identifier creates a thread through the activity so a maintainer can distinguish one execution from another.

Run structure

[RUN START][job_batch_20260403_211500]
Processed : 2
Success : 1
Failed : 1
[RUN END]

A batch contains a start boundary, per-item activity, and an end summary. This makes the execution understandable without relying on memory.

Item tracking

StatusSUCCESS, ERROR, or SENT.
IdentitySubject or filename associated with the item.
StageWhere the item was when the event occurred.
TimestampWhen the event occurred.

Error handling and recovery

Errors are categorized, logged, and isolated from successful items. Processing continues when possible. This means one failed item does not automatically erase the value of the rest of the batch.

Supportability matters

The logs and folders are part of the workflow itself. They reduce the need to guess whether an email was processed, sent, skipped, or failed.
